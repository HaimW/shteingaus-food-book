# חיבור האתר לתיקיית המתכונים ב-Google Drive

המדריך הזה מחבר את האתר לתיקייה ב-Google Drive. אחרי ההגדרה, כל מתכון שנכתב כמסמך Google Docs בתיקייה מופיע באתר אוטומטית: פעם ביום, או מיד כשמפעילים סנכרון ידני.

**זמן משוער:** כ-15 דקות, פעם אחת בלבד. לא צריך לדעת לתכנת.

> **חשוב לדעת: האתר ציבורי.** כל מה שנכתב במסמכים בתיקייה (כולל שמות, הערות ותמונות) יופיע באתר שכל אחד יכול לראות. גם המסמכים שבתיקייה וההיסטוריה שלהם נשמרים במאגר הקוד הציבורי ב-GitHub. לא שמים בתיקייה מידע פרטי.

## מה צריך מראש

- חשבון Google (זה שבו נמצאת, או תהיה, תיקיית המתכונים).
- גישת מנהל למאגר `haimw/shteingaus-food-book` ב-GitHub.

## איך זה עובד (בקצרה)

1. בני המשפחה כותבים מתכונים כמסמכי Google Docs בתיקייה אחת ב-Drive.
2. "חשבון שירות" (service account) — מעין משתמש-רובוט של Google — מקבל הרשאת **צפייה בלבד** לתיקייה.
3. פעם ביום (וגם כשמפעילים ידנית) GitHub מריץ את הסנכרון: קורא את המסמכים, הופך אותם לדפי מתכון עם תמונות, ומעדכן את האתר.
4. אם משהו חסר במתכון (מצרכים, תמונה, ארוחה, סוג מנה) — המתכון עדיין מתפרסם, עם תיבה צהובה "צריך לתקן", והוא מופיע בדף **"צריך לתקן"**: https://haimw.github.io/shteingaus-food-book/needs-fixing/ (הדף לא מופיע בתפריט; כדאי לשמור את הקישור).

## שלב 1: יצירת פרויקט ב-Google Cloud

1. נכנסים ל-https://console.cloud.google.com/ עם חשבון ה-Google שלכם. אם זו הפעם הראשונה, מאשרים את תנאי השימוש.
2. למעלה, ליד הלוגו, לוחצים על בורר הפרויקטים ← **New project** (פרויקט חדש).
3. שם הפרויקט: `shteingaus-food-book` ← **Create**. לא צריך חשבון חיוב (Billing) — השימוש חינמי.
4. מוודאים שהפרויקט החדש נבחר בבורר הפרויקטים למעלה.

## שלב 2: הפעלת Google Drive API

1. בתפריט הראשי (שלושת הקווים למעלה) ← **APIs & Services** ← **Library** (ספרייה).
2. מחפשים **Google Drive API**, לוחצים עליו ← **Enable** (הפעלה).

## שלב 3: יצירת חשבון שירות ומפתח

1. בתפריט ← **IAM & Admin** ← **Service Accounts** ← **Create service account**.
2. שם: `recipes-sync` ← **Create and continue**. בשלבים "Grant access" ו-"Grant users" **לא בוחרים כלום** ← **Done**.
3. ברשימה מופיע עכשיו חשבון עם כתובת כמו `recipes-sync@shteingaus-food-book.iam.gserviceaccount.com`. **מעתיקים את הכתובת הזו** — נצטרך אותה בשלב 4.
4. לוחצים על החשבון ← לשונית **Keys** ← **Add key** ← **Create new key** ← **JSON** ← **Create**. קובץ `.json` יורד למחשב.

> **הקובץ הזה הוא סיסמה.** לא שולחים אותו במייל או בוואטסאפ ולא מעלים אותו ל-Drive או ל-GitHub כקובץ. משתמשים בו רק בשלב 5, ואחר כך אפשר למחוק אותו מהמחשב (תמיד אפשר ליצור מפתח חדש).
>
> אם Google מציגה שגיאה שיצירת מפתחות חסומה ("Service account key creation is disabled") — זה קורה בחשבונות של ארגון/Workspace. במקרה כזה עדיף ליצור את הפרויקט עם חשבון Gmail פרטי, או לבקש ממנהל הארגון לאפשר זאת.

## שלב 4: תיקיית המתכונים ב-Drive ושיתוף עם חשבון השירות

1. ב-https://drive.google.com/ יוצרים תיקייה בשם **מתכונים לאתר** (או משתמשים בתיקייה קיימת).
2. לוחצים על התיקייה בכפתור ימני ← **שיתוף** ← מדביקים את כתובת חשבון השירות משלב 3, הרשאה: **צפייה** (Viewer) ← מבטלים את הסימון "שליחת הודעה" ← **שיתוף**.
3. משתפים את התיקייה גם עם בני המשפחה שיכתבו מתכונים, בהרשאת **עריכה**.
4. **מזהה התיקייה:** פותחים את התיקייה. הכתובת בדפדפן נראית כך:
   `https://drive.google.com/drive/folders/1AbCdEfGhIjKlMnOpQrStUvWxYz`
   החלק שאחרי `folders/` (כאן `1AbCdEfGhIjKlMnOpQrStUvWxYz`) הוא מזהה התיקייה. מעתיקים אותו.

הסנכרון קורא רק מסמכים שנמצאים **ישירות** בתיקייה (לא בתתי-תיקיות), ורק מסמכי Google Docs.

## שלב 5: הכנסת המפתח ומזהה התיקייה ל-GitHub

1. ב-GitHub פותחים את המאגר ← **Settings** ← בתפריט הצד **Secrets and variables** ← **Actions**.
2. לשונית **Secrets** ← **New repository secret**:
   - Name: `GOOGLE_SERVICE_ACCOUNT_KEY`
   - Secret: פותחים את קובץ ה-JSON משלב 3 בעורך טקסט (Notepad / TextEdit), מעתיקים **את כל התוכן** — מה-`{` הראשון עד ה-`}` האחרון — ומדביקים.
   - **Add secret**.
3. לשונית **Variables** ← **New repository variable**:
   - Name: `DRIVE_FOLDER_ID`
   - Value: מזהה התיקייה משלב 4.
   - **Add variable**.

עד שהשלב הזה נעשה, הסנכרון היומי פשוט מדלג (עם הודעה "Drive sync not configured") ולא נכשל.

## שלב 6: הרצת סנכרון ראשון

1. במאגר ב-GitHub ← לשונית **Actions** ← בצד: **Sync recipes from Google Drive** ← **Run workflow** ← **Run workflow** (על ענף `main`).
2. אחרי דקה-שתיים הריצה מסתיימת:
   - **סימן ירוק** — הסנכרון הצליח. לוחצים על הריצה כדי לראות סיכום: מה נוסף, עודכן, נמחק, ואילו מתכונים צריכים תיקון. אם היו שינויים, האתר מתעדכן תוך כ-2–3 דקות נוספות (שלב "deploy").
   - **סימן אדום** — משהו בהגדרה לא תקין, והאתר נשאר כמו שהיה. ההודעה בריצה אומרת מה הבעיה, למשל:
     - *rejected the service account credentials* — המפתח ב-`GOOGLE_SERVICE_ACCOUNT_KEY` שגוי או נמחק; חוזרים לשלב 3 (מפתח חדש) ושלב 5.
     - *folder … not found* — מזהה התיקייה שגוי, או שהתיקייה לא שותפה עם כתובת חשבון השירות (שלב 4).
     - *has no Google Docs, but N recipes came from it* — התיקייה נראית ריקה פתאום; הסנכרון מסרב למחוק את כל המתכונים מהאתר. בודקים שהמזהה והשיתוף נכונים.
3. הסנכרון רץ מעכשיו לבד כל יום בבוקר.

> GitHub משבית ריצות מתוזמנות במאגר שלא היה בו שום שינוי במשך 60 יום. אם זה קורה, מופיעה הודעה בלשונית Actions ואפשר להפעיל מחדש בלחיצה (**Enable workflow**).

## שלב 7: העברת המתכונים הקיימים

- מעבירים או מעתיקים את מסמכי ה-Google Docs הקיימים לתיקייה. הסנכרון הבא מייבא את כולם.
- קבצי Word (`.docx`) שהועלו ל-Drive: פותחים כל אחד ב-Google Docs ← **קובץ** ← **שמירה כ-Google Docs**, ומוחקים (או מוציאים מהתיקייה) את קובץ ה-Word. קבצים שאינם מסמכי Google Docs מדולגים, ומופיעים בסיכום הסנכרון תחת "Skipped files".
- מתכונים ישנים שלא כתובים לפי התבנית עדיין יתפרסמו: מה שלא מזוהה נכנס לגוף המתכון, ומה שחסר מופיע בדף "צריך לתקן".

## הוספת מתכון חדש

### הכנת התבנית (פעם אחת)

1. מורידים את [`docs/recipe-template.docx`](recipe-template.docx) מהמאגר (בעמוד הקובץ ב-GitHub: כפתור ההורדה).
2. מעלים אותו ל-**האחסון שלי** ב-Drive — **לא** לתיקיית המתכונים, כדי שהתבנית עצמה לא תתפרסם כמתכון.
3. פותחים אותו ב-Google Docs ← **קובץ** ← **שמירה כ-Google Docs**. משנים את שם המסמך ל-**תבנית מתכון**, ומוחקים את קובץ ה-`.docx`.

### כל מתכון חדש

1. על **תבנית מתכון**: **קובץ** ← **יצירת עותק** ← שם העותק = **שם המתכון** (למשל "עוגת הגבינה של סבתא"), ותיקייה = **מתכונים לאתר**.
   - שם המסמך הוא שם המתכון באתר. אם נשאר "עותק של …", החלק הזה מוסר אוטומטית.
2. ממלאים את הטבלה, מדביקים תמונות, וכותבים מתחת לכותרות (ראו מבנה התבנית למטה).
3. מפעילים סנכרון (שלב 6) או מחכים לסנכרון היומי. המתכון מופיע באתר.

**עריכה:** משנים את המסמך ב-Drive — לא באתר ולא ב-GitHub. הסנכרון הבא מעדכן את האתר. שינוי שם המסמך משנה את הכותרת באתר, אבל **הכתובת (URL) של המתכון לא משתנה**.
**מחיקה:** מוחקים את המסמך או מוציאים אותו מהתיקייה; הסנכרון הבא מסיר את המתכון מהאתר.

### מבנה התבנית

| חלק | מה כותבים | הערות |
|---|---|---|
| **שם המסמך** | שם המתכון | הופך לכותרת באתר |
| טבלה: **ארוחה** | ארוחת בוקר / ארוחת צהריים / ארוחת ערב / קינוח | אפשר כמה, מופרדים בפסיק. מתקבלים גם: בוקר, צהריים, ערב |
| טבלה: **סוג מנה** | מנה עיקרית / תוספת / סלט / קינוח / אחר | אפשר כמה, מופרדים בפסיק (למשל "סלט, תוספת"). מתקבל גם "חלבון" או "עיקרית". משמש את "בנה לי ארוחה" |
| טבלה: **מאת** | ממי המתכון | לא חובה |
| טבלה: **מנות**, **זמן הכנה**, **זמן בישול** | טקסט חופשי, למשל "45 דקות" | לא חובה |
| טבלה: **slug** | כתובת באנגלית, למשל `grandma-cheesecake` | לא חובה. אם ריק — נוצרת כתובת אוטומטית מהשם בעברית (בתעתיק, למשל `ogt-hgvina-shl-svta`), והיא נשארת קבועה גם אם שם המסמך משתנה. מילוי ה-slug מאוחר יותר משנה את הכתובת |
| **תמונות** | מדביקים בכל מקום במסמך | **הראשונה היא התמונה הראשית** של המתכון. השאר מופיעות בגוף המתכון במקום שבו הודבקו. התמונות מוקטנות ונדחסות אוטומטית |
| כותרת **מצרכים** | מצרך אחד בכל שורה: כמות ואז מצרך ("2 כוסות קמח") | רשימת תבליטים או שורות רגילות. כותרות משנה כמו "לבצק:" נשמרות. בלי מצרכים — המתכון מתפרסם עם אזור אדום "מצרכים חסרים" |
| כותרת **אופן ההכנה** | השלבים | רשימה ממוספרת או פסקאות |
| כותרת **הערות** | טיפים, החלפות, הגשה | לא חובה |
| שורות **"הנחיה: …"** | הסברים בתוך התבנית | לא מופיעות באתר; אפשר למחוק |

**כותרות:** עדיף להשתמש בסגנון "כותרת 2" של Google Docs (כמו בתבנית), אבל גם שורה מודגשת בשם "מצרכים" / "אופן ההכנה" / "הערות" (עם או בלי נקודתיים) מזוהה ככותרת. מוכרים גם: רכיבים, חומרים, הוראות הכנה, טיפים.
**בלי טבלה:** אפשר גם לכתוב את הפרטים בשורות בראש המסמך, למשל `ארוחה: ארוחת ערב`.
**מה שלא מזוהה** (טקסט חופשי, טבלאות אחרות, כותרות אחרות) נשמר בגוף המתכון — שום דבר לא הולך לאיבוד, והסנכרון לא נכשל בגלל תוכן.

## דף "צריך לתקן"

https://haimw.github.io/shteingaus-food-book/needs-fixing/ — רשימת כל המתכונים שחסר בהם משהו (מצרכים, תמונה, ארוחה, סוג מנה, או ערך לא מוכר), עם קישור לדף המתכון ולמסמך ב-Google Docs לתיקון. הדף לא מופיע בתפריט ולא במנועי חיפוש. גם בסיכום של כל ריצת סנכרון ב-GitHub מופיעה הרשימה.

## לשימוש מתקדם

- **הרצה מקומית:** `GOOGLE_SERVICE_ACCOUNT_KEY=path/to/key.json DRIVE_FOLDER_ID=... npm run sync`. בלי חשבון Google אפשר לנסות על מסמכי דוגמה: `npm run sync -- --mock-drive tests/fixtures/drive` (זה כותב מתכוני דוגמה לתוך `src/content/recipes/` — לא לבצע commit שלהם).
- **המרה מחדש של הכול** (אחרי שינוי בקוד הממיר): ב-Run workflow מסמנים **force**.
- **כשהתיקייה באמת ריקה בכוונה:** הסנכרון מסרב למחוק את כל המתכונים. מריצים מקומית עם `SYNC_ALLOW_EMPTY=1`.
- **ביטול הגישה:** ב-Google Cloud ← Service Accounts ← מוחקים את המפתח (Keys) או את החשבון; או מבטלים את השיתוף של התיקייה.
- **אם הפרסום (deploy) נכשל אחרי סנכרון מוצלח:** השינויים כבר שמורים ב-`main`; מריצים ידנית את **Deploy to GitHub Pages** ב-Actions.
